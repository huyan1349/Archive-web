### 微信读书一键导入功能（浏览器扩展方案）

**背景**：用户要求微信读书导入做到"一键"，不希望手动操作太多。
由于浏览器安全限制，网页无法自动读取另一个站点的 Cookie，唯一的真正
"一键"方案是做浏览器扩展。

**实现内容**：

1. **浏览器扩展** (`extension/` 目录，Manifest V3)
   - `manifest.json`：申请 `cookies` 和 `storage` 权限
   - `popup.html/js`：弹出窗口，检测 weread.qq.com 登录态，
     点击后将 Cookie 写入 `chrome.storage.local`
   - `content.js`：注入到 localhost:5173，监听 storage 变化，
     收到 Cookie 后通过 `CustomEvent('lucerna:weread-cookie')` 传给 React 应用

2. **App.tsx 改造**
   - 新增 `wereadCookieFromExt` state，接收扩展传来的 Cookie
   - 新增 `useEffect` 监听 `lucerna:weread-cookie` 事件
   - 改造 `handleWeReadSync(cookieFromExt?)`：优先用扩展传来的 Cookie，
     手动粘贴的作为 fallback
   - 同步结束后 dispatch `lucerna:weread-cookie-processed` 通知扩展清 storage

3. **UI 更新**
   - 设置页微信读书区域新增扩展提示条
   - `App.css` 新增 `.weread-ext-hint` / `.weread-ext-icon` 样式

4. **扩展使用文档** `extension/README.md`

## 技术决策

- 用 `chrome.storage.local` 做扩展与 content script 之间的传值，
  不走 Vite 中间件，避免额外服务依赖
- content script 注入 localhost 页面，通过 CustomEvent 与 React 通信，
  这是 Manifest V3 扩展与 web 应用通信的标准做法

## Chrome 扩展 Cookie 读取方案重写 (18:20)

- 问题：之前只靠 webRequest.onBeforeSendHeaders 捕获 cookie，需要浏览器恰好发起请求才能拿到，经常失败；chrome.cookies.getAll 用 domain 参数也返回 0 条
- 研究：搜索 GitHub 上 wereader、wxread-export 等成熟项目，发现最靠谱的方式是 `chrome.cookies.getAll({ url: 'https://weread.qq.com' })` （用 url 参数而非 domain），以及 content script 读 document.cookie
- 方案：三重保障 — ①popup 直接调 cookies API (url 参数) ②cookies API (domain 参数兜底) ③scripting.executeScript 注入 weread 页面读 document.cookie ④保留 webRequest 拦截 ⑤新增 weread-content.js 主动读取
- 拆分 content.js 为 lucerna-content.js (localhost:5177) 和 weread-content.js (weread.qq.com)
- manifest 新增 scripting、activeTab 权限，版本号升到 1.1
- 关键 cookie 名：wr_skey (认证 token, 90分钟过期)、wr_vid (用户 ID, 长期)

## 扩展改为"读取+展示+一键复制"方案 (19:38)

- 问题：自动传值（content script → React）因 Chrome 隔离世界问题始终不通，注入脚本 + postMessage + CustomEvent 三种方式都没成功
- 新方案：放弃自动传值，改为 popup 直接读取 Cookie → 展示在文本框 → 用户点「复制 Cookie」→ 去 LUCERNA 粘贴
- popup.html 完全重写：textarea 展示 cookie + 复制按钮 + 重新读取按钮
- popup.js 简化：去掉 sendToLucerna / storage 写入 / tabs 操作，只做读取和展示
- 两条读取路径：① chrome.cookies.getAll({ url }) ② scripting.executeScript 读 document.cookie
- 用户流程：扩展图标 → 看到 Cookie → 复制 → 粘贴到 LUCERNA 的 Cookie 输入框 → 点同步

## Cookie 无效问题修复 (19:41)

- 问题：能读取到 cookie 但导入 LUCERNA 后显示"Cookie 无效"
- 原因分析：1) 只读了 weread.qq.com 的 cookie，没合并 i.weread.qq.com 的（WeReadClient API 走的是 i.weread.qq.com）2) validate 失败时没有显示具体原因
- 修复：popup.js 改为同时读取两个域名的 cookie 并合并去重
- 修复：WeReadClient.validate() 改为返回 { valid, error } 结构，App.tsx 和 DevPanel 都展示具体错误
- popup.html 新增 cookie-names 展示，方便用户看到读到了哪些 cookie
